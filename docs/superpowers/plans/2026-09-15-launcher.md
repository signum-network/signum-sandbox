# The Launcher and the One-Liner — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command installs the sandbox — including a private Java the user never hears about — and runs it, on macOS and Linux.

**Architecture:** One POSIX `sh` file is the launcher and holds every decision. `install.sh` is a bootstrap that fetches the release zip, unpacks it, and hands over to the launcher inside it, so the JRE handling and the on-disk layout exist in exactly one place. Everything that is a decision rather than an effect takes its inputs as arguments and returns a string, which is what makes it testable in a plain `sh` test script.

**Tech Stack:** POSIX `sh` (not bash — macOS ships bash 3.2 and Debian's `/bin/sh` is dash), `curl`, `tar`, `unzip`, `shasum`/`sha256sum`. No jq, no node, no bun at run time.

**Spec:** `docs/superpowers/specs/2026-09-15-launcher-and-installer-design.md`

---

## Things to know before starting

1. **POSIX `sh`, strictly.** No arrays, no `[[`, no `local`, no `${var,,}`, no process substitution. macOS `/bin/sh` is bash 3.2 in POSIX mode; Debian's is dash. If it works in dash it works everywhere. Check with `dash scripts/launcher.test.sh` if dash is available, otherwise `sh` on macOS is a good-enough proxy for the syntax subset used here.

2. **Every decision takes its inputs as arguments.** `platform_id "$(uname -s)" "$(uname -m)"`, not `platform_id` reading `uname` itself. That single habit is what makes the test script possible without mocking anything.

3. **The launcher must be sourceable without running.** The last lines are guarded by `LAUNCHER_LIB_ONLY`, so the test script can source it and call functions.

4. **`set -eu`, never `set -e` alone**, and no `pipefail` — dash does not have it.

5. **Verified facts this plan hardcodes** (checked by running it, do not re-derive):
   - The JRE tarball's top-level directory is `jdk-21.0.12.1+1-jre` on both platforms.
   - `java` is at `Contents/Home/bin/java` inside it on macOS, `bin/java` on Linux.
   - The four SHA-256 sums are in Task 1.
   - The node answers on **6876** because that is the mock/test network's default. `API.Port` appears only commented out in `conf/node-default.properties` (with the mainnet value `8125`), so the port is not in any file unless a user puts it there.
   - `scripts/package.sh` zips a directory named `signum-sandbox-<version>`, so the archive has exactly one top-level directory.

6. **Do not touch `html/api-doc`.** `scripts/bootstrap.sh` does `rm -rf html/api-doc` and re-copies it from the node release.

Create `scripts/signum-sandbox`:

```sh
#!/bin/sh
# The Signum Sandbox launcher.
#
# It installs what the sandbox needs — a private Java among it — and runs the
# node. One file on purpose: the alternative was a library plus a front end,
# and this is small enough that splitting it would only make it harder to read
# in one sitting.
#
# POSIX sh, strictly. macOS ships bash 3.2 and Debian's /bin/sh is dash, so
# no arrays, no [[, no local, no pipefail.
#
# Every decision in here takes its inputs as arguments and returns a string,
# rather than reading the world itself. That is what lets
# scripts/launcher.test.sh call them without mocking anything.
set -eu

# ── where everything lives ─────────────────────────────────────
HOME_DIR="${SIGNUM_SANDBOX_HOME:-$HOME/.signum-sandbox}"
APP_DIR="$HOME_DIR/app"
JRE_DIR_BASE="$HOME_DIR/jre"
CONF_DIR="$HOME_DIR/conf"
HTML_DIR="$HOME_DIR/html"
LOG_FILE="$HOME_DIR/logs/node.log"
PID_FILE="$HOME_DIR/run/node.pid"
INSTALLED_FILE="$HOME_DIR/installed"

# SIGNUM_SANDBOX_HOME is not advertised in --help: it exists so the tests and
# the container run can work somewhere other than a real home directory.

REPO='signum-network/signum-sandbox'
DEFAULT_PORT=6876

say()  { printf '%s\n' "$*"; }
warn() { printf '%s\n' "$*" >&2; }
die()  { printf '%s\n' "$*" >&2; exit 1; }

# ── the pinned JRE ─────────────────────────────────────────────
# Sourced from beside this script when running from a checkout or a release,
# and from the app directory once installed.
load_pinned() {
  for candidate in \
    "$(dirname -- "$0")/jre.pinned" \
    "$APP_DIR/$(cat "$INSTALLED_FILE" 2>/dev/null || echo none)/scripts/jre.pinned"
  do
    if [ -f "$candidate" ]; then
      . "$candidate"
      return 0
    fi
  done
  die 'launcher: cannot find jre.pinned — the installation is incomplete'
}
load_pinned

# ── decisions ──────────────────────────────────────────────────

# platform_id <uname -s> <uname -m> -> mac_aarch64 | mac_x64 | linux_x64 | linux_aarch64
#
# Prints nothing and fails for anything else, so the caller can say what it
# found rather than building a URL that 404s much later for a reason nobody
# can read.
platform_id() {
  case "$1" in
    Darwin) os=mac ;;
    Linux)  os=linux ;;
    *)      return 1 ;;
  esac
  case "$2" in
    arm64|aarch64) arch=aarch64 ;;
    x86_64|amd64)  arch=x64 ;;
    *)             return 1 ;;
  esac
  printf '%s_%s' "$os" "$arch"
}

# jre_url <platform_id> -> the Adoptium download for the pinned version.
#
# The `version` endpoint rather than `latest`, so the checksum beside it in
# jre.pinned stays true. "+" has to be percent-encoded or the API answers 404.
jre_url() {
  encoded=$(printf '%s' "$JRE_VERSION" | sed 's/+/%2B/')
  case "$1" in
    mac_aarch64)   printf 'https://api.adoptium.net/v3/binary/version/jdk-%s/mac/aarch64/jre/hotspot/normal/eclipse' "$encoded" ;;
    mac_x64)       printf 'https://api.adoptium.net/v3/binary/version/jdk-%s/mac/x64/jre/hotspot/normal/eclipse' "$encoded" ;;
    linux_x64)     printf 'https://api.adoptium.net/v3/binary/version/jdk-%s/linux/x64/jre/hotspot/normal/eclipse' "$encoded" ;;
    linux_aarch64) printf 'https://api.adoptium.net/v3/binary/version/jdk-%s/linux/aarch64/jre/hotspot/normal/eclipse' "$encoded" ;;
    *)             return 1 ;;
  esac
}

# jre_sha <platform_id> -> the pinned checksum.
#
# A case rather than indirect expansion, because ${!var} is a bashism and
# eval for this would be a sharp tool for no gain.
jre_sha() {
  case "$1" in
    mac_aarch64)   printf '%s' "$JRE_SHA_mac_aarch64" ;;
    mac_x64)       printf '%s' "$JRE_SHA_mac_x64" ;;
    linux_x64)     printf '%s' "$JRE_SHA_linux_x64" ;;
    linux_aarch64) printf '%s' "$JRE_SHA_linux_aarch64" ;;
    *)             return 1 ;;
  esac
}

# java_binary <platform_id> <jre base dir> -> the java to run.
#
# The layout difference is Temurin's: a macOS JRE is an app bundle with
# Contents/Home, a Linux one is not.
java_binary() {
  case "$1" in
    mac_*)   printf '%s/%s/Contents/Home/bin/java' "$2" "$JRE_DIR" ;;
    linux_*) printf '%s/%s/bin/java' "$2" "$JRE_DIR" ;;
    *)       return 1 ;;
  esac
}

# ── entry point ────────────────────────────────────────────────
main() {
  die 'launcher: not implemented yet'
}

# Sourced by the test script, which wants the functions and not the program.
if [ "${LAUNCHER_LIB_ONLY:-0}" != "1" ]; then
  main "$@"
fi
```

```sh
# installed_version <path to the installed file> -> the active version, or ''.
#
# The active version is a plain file and not a symlink, so that the later
# Windows variant needs no privileges and so that looking at the directory
# tells you the truth without interpreting a link.
installed_version() {
  [ -f "$1" ] || return 0
  tr -d '\n' < "$1"
}

# html_needs_copy <wanted version> <path to html/.version> -> yes | no
#
# The node resolves API.UI_Dir relatively, so the html it serves has to sit at
# $HOME_DIR/html under exactly that name — which is why it is a copy of the
# active release's rather than a link into it. 2MB, about 84ms, and only when
# the version changed.
html_needs_copy() {
  [ -f "$2" ] || { printf 'yes'; return 0; }
  if [ "$(tr -d '\n' < "$2")" = "$1" ]; then printf 'no'; else printf 'yes'; fi
}

# prune_list <app dir> <version to keep>... -> the releases to delete, one
# per line.
#
# Each release is about 64MB, almost all of it the node jar, so without this
# ~/.signum-sandbox grows into the gigabytes and nobody notices.
#
# The versions to keep are named, not derived from modification time. Sorting
# by mtime and keeping the two newest looks equivalent and is not: mv
# preserves the mtime the archive carried, so the release just installed is
# not reliably the newest on disk. Named, nothing in use can be deleted by
# construction.
prune_list() {
  dir=$1
  shift
  # shellcheck disable=SC2045  # these names are versions; no spaces to fear
  for existing in $(ls -1 "$dir" 2>/dev/null); do
    keep=no
    for wanted in "$@"; do
      if [ "$existing" = "$wanted" ]; then keep=yes; fi
    done
    if [ "$keep" = 'no' ]; then printf '%s\n' "$existing"; fi
  done
  return 0
}
```

# sha256_of <file> -> the hex sum.
#
# macOS has shasum, most Linux distributions have sha256sum, and a few have
# both. Checking for each is cheaper than depending on one and being wrong on
# somebody's machine.
sha256_of() {
  if command -v shasum >/dev/null 2>&1; then
    shasum -a 256 "$1" | cut -d' ' -f1
  elif command -v sha256sum >/dev/null 2>&1; then
    sha256sum "$1" | cut -d' ' -f1
  else
    die 'launcher: no shasum or sha256sum on this machine, cannot verify a download'
  fi
}

# fetch <url> <destination>
#
# -f so a 404 is a failure rather than a file containing an error page, -L
# because both GitHub and Adoptium redirect, and --retry because a download of
# 50MB deserves one.
fetch() {
  command -v curl >/dev/null 2>&1 || die 'launcher: curl is required'
  curl -fL --retry 2 --progress-bar -o "$2" "$1" \
    || die "launcher: could not download $1"
}

# verify <file> <expected sum> <what it is, for the message>
verify() {
  actual=$(sha256_of "$1")
  [ "$actual" = "$2" ] && return 0
  warn "launcher: $3 does not match its checksum."
  warn "  expected $2"
  warn "  got      $actual"
  die  'launcher: refusing to install it'
}
```

# ensure_jre <platform_id>
#
# Idempotent: an existing, runnable java at the pinned version is left alone,
# so a second install or an update does not re-download 50MB.
#
# The private JRE is used even when the machine has a system Java, because one
# variable fewer is worth 50MB when something breaks for a user who cannot be
# looked over the shoulder of. SIGNUM_SANDBOX_JAVA is the way out for whoever
# wants their own.
ensure_jre() {
  if [ -n "${SIGNUM_SANDBOX_JAVA:-}" ]; then
    [ -x "$SIGNUM_SANDBOX_JAVA" ] || die "launcher: SIGNUM_SANDBOX_JAVA is not executable: $SIGNUM_SANDBOX_JAVA"
    say "launcher: using the Java you pointed at: $SIGNUM_SANDBOX_JAVA"
    return 0
  fi

  java=$(java_binary "$1" "$JRE_DIR_BASE")
  if [ -x "$java" ]; then
    return 0
  fi

  say "launcher: fetching Java $JRE_VERSION (about 50 MB, once)"
  mkdir -p "$JRE_DIR_BASE"
  tarball="$JRE_DIR_BASE/.download.tar.gz"
  fetch "$(jre_url "$1")" "$tarball"
  verify "$tarball" "$(jre_sha "$1")" "the Java download"
  tar -xzf "$tarball" -C "$JRE_DIR_BASE"
  rm -f "$tarball"
  [ -x "$java" ] || die "launcher: the Java archive did not contain $java"
}
```

# active_app -> the directory of the release that is live, or die trying.
active_app() {
  version=$(installed_version "$INSTALLED_FILE")
  [ -n "$version" ] || die 'launcher: nothing is installed yet — run the installer'
  dir="$APP_DIR/$version"
  [ -d "$dir" ] || die "launcher: $INSTALLED_FILE names $version but $dir is missing"
  printf '%s' "$dir"
}

# prepare_layout <app dir> <version>
#
# Everything the node needs to find from $HOME_DIR, which is its working
# directory. conf/node.properties points at ./db and html/sandbox relatively,
# so both have to resolve from there — and neither may carry a version number,
# or an update would have to rewrite a file the launcher promised to leave
# alone.
prepare_layout() {
  mkdir -p "$CONF_DIR" "$HOME_DIR/db" "$HOME_DIR/logs" "$HOME_DIR/run"

  # The node's own defaults belong to the release and are replaced with it.
  cp "$1/conf/node-default.properties" "$CONF_DIR/node-default.properties"
  cp "$1/conf/logging-default.properties" "$CONF_DIR/logging-default.properties"

  # Ours is seeded once and never touched again, so a changed port survives
  # every update.
  if [ ! -f "$CONF_DIR/node.properties" ]; then
    cp "$1/conf/node.properties" "$CONF_DIR/node.properties"
  fi

  if [ "$(html_needs_copy "$2" "$HTML_DIR/.version")" = 'yes' ]; then
    rm -rf "$HTML_DIR"
    cp -R "$1/html" "$HTML_DIR"
    printf '%s\n' "$2" > "$HTML_DIR/.version"

# node_port -> the port to talk to.
#
# 6876 is the mock network's own default; API.Port appears in
# node-default.properties only commented out, with the mainnet value. So the
# only place a port can really come from is a user who set one.
node_port() {
  port=$(sed -n 's/^[[:space:]]*API\.Port[[:space:]]*=[[:space:]]*\([0-9]\{1,\}\).*/\1/p' \
    "$CONF_DIR/node.properties" 2>/dev/null | head -1)

cmd_start() {
  daemon=no
  for arg in "$@"; do
    case "$arg" in
      --daemon) daemon=yes ;;
      *) die "start: unknown option $arg" ;;
    esac
  done

  plat=$(platform_id "$(uname -s)" "$(uname -m)") \
    || die "launcher: unsupported platform: $(uname -s) $(uname -m)"
  app=$(active_app)
  version=$(installed_version "$INSTALLED_FILE")
  ensure_jre "$plat"
  prepare_layout "$app" "$version"

  java=${SIGNUM_SANDBOX_JAVA:-$(java_binary "$plat" "$JRE_DIR_BASE")}
  port=$(node_port)

  if is_running; then
    die "launcher: already running (pid $(cat "$PID_FILE")) — stop it first"
  fi

  cd "$HOME_DIR"
  if [ "$daemon" = 'yes' ]; then
    # nohup and a pidfile, deliberately not launchd or systemd: one mechanism
    # for both platforms, and a sandbox that does not quietly outlive the
    # session that started it.
    nohup "$java" -jar "$app/signum-node.jar" --headless -c ./conf/ \
      >> "$LOG_FILE" 2>&1 &
    printf '%s\n' "$!" > "$PID_FILE"
    say "launcher: running in the background on http://localhost:$port/"
    say "launcher: signum-sandbox logs   to watch it"
    say "launcher: signum-sandbox stop   to end it"
  else
    say "launcher: http://localhost:$port/  (Ctrl-C to stop)"
    exec "$java" -jar "$app/signum-node.jar" --headless -c ./conf/
  fi
}

#
# kill -0 asks the kernel whether the signal could be delivered without

is_running() {

cmd_stop() {
  if ! is_running; then
    say 'launcher: not running'
    return 0
  fi
  pid=$(cat "$PID_FILE")
  kill "$pid" 2>/dev/null || true
  # The node closes its database on SIGTERM; give it a moment before saying
  # anything, so "stopped" is not printed over a process still writing.
  i=0
  while [ "$i" -lt 30 ] && kill -0 "$pid" 2>/dev/null; do
    sleep 0.2
    i=$((i + 1))
  done
  if kill -0 "$pid" 2>/dev/null; then
    warn "launcher: pid $pid did not stop; leaving it alone rather than forcing it"
    return 1
  fi
  rm -f "$PID_FILE"
  say 'launcher: stopped'
}

cmd_status() {
  version=$(installed_version "$INSTALLED_FILE")
  [ -n "$version" ] || { say 'launcher: nothing installed'; return 0; }
  say "version: $version"

  port=$(node_port)
  if is_running; then
    say "process: running in the background (pid $(cat "$PID_FILE"))"
  else
    say 'process: no background node (one may be running in the foreground)'
  fi

  # Asked of the node rather than inferred from the pid: a process that is
  # alive but not answering is the failure worth seeing.
  status=$(curl -fsS -m 3 "http://localhost:$port/api?requestType=getBlockchainStatus" 2>/dev/null || true)
  if [ -n "$status" ]; then
    height=$(printf '%s' "$status" | sed -n 's/.*"numberOfBlocks":[[:space:]]*\([0-9]\{1,\}\).*/\1/p')
    say "node:    answering on port $port, height ${height:-unknown}"
  else
    say "node:    nothing answering on port $port"
  fi
}

cmd_logs() {
  if [ -f "$NODE_LOG" ]; then
    # The node's own log is the operational one and is what anyone asking for
    # logs wants. Our capture of stdout largely duplicates it — once the node
    # has configured logging it prints to the console as well — so following
    # both would show nearly every line twice. What the capture has that this
    # does not is whatever the JVM said before logging existed, which is where
    # a failure to start lands, so it gets named rather than followed.
    [ -f "$LOG_FILE" ] && say "launcher: startup output, if you need it: $LOG_FILE"
    tail -f "$NODE_LOG"
  elif [ -f "$LOG_FILE" ]; then
    warn 'launcher: the node kept no log of its own — it may not have got that far.'
    tail -f "$LOG_FILE"
  else
    die 'launcher: no log yet — has it ever started?'
  fi
}

# reset_verdict <running: yes|no> <confirmed: yes|no> -> delete | refuse | cancelled
#
# A running node holds its database open, and deleting it underneath is how a
# chain becomes half a chain. Before there was a pidfile this was a warning in
# a comment; now it is a check. Running loses over confirmation deliberately:
# someone who typed yes to a prompt has not thereby stopped the node.
reset_verdict() {
  if [ "$1" = 'yes' ]; then printf 'refuse'; return 0; fi
  if [ "$2" = 'yes' ]; then printf 'delete'; else printf 'cancelled'; fi
}

cmd_reset() {
  if is_running; then running=yes; else running=no; fi

  confirmed=no
  if [ "$running" = 'no' ]; then
    printf 'launcher: delete the chain in %s/db and start from empty? [y/N] ' "$HOME_DIR"
    read -r answer || answer=''
    case "$answer" in y|Y|yes|YES) confirmed=yes ;; esac
  fi

  case "$(reset_verdict "$running" "$confirmed")" in
    refuse)
      die 'launcher: the node is running and holds the chain open. Run "signum-sandbox stop" first.'
      ;;
    delete)
      rm -rf "$HOME_DIR/db"
      say 'launcher: chain deleted'
      ;;
    cancelled)
      say 'launcher: kept the existing chain'
      ;;
  esac
}

# latest_tag <the releases/latest JSON> -> the version, or ''.
#
# sed rather than jq, which cannot be assumed to exist. It reads one field out
# of one object, which is the whole reason this is tolerable: anything more
# structured than that belongs in a language with a JSON parser.
latest_tag() {
  printf '%s' "$1" \
    | sed -n 's/.*"tag_name"[[:space:]]*:[[:space:]]*"v\{0,1\}\([^"]*\)".*/\1/p' \
    | head -1
}

# release_url <version> -> where that release's zip lives.
release_url() {
  printf 'https://github.com/%s/releases/download/v%s/signum-sandbox-%s.zip' \
    "$REPO" "$1" "$1"
}

# install_release <version> <zip>
#
# Unpacks beside whatever is live and only then writes the version file, so an
# interrupted download leaves a directory nobody uses rather than a broken
# installation. package.sh zips a single top-level directory named
# signum-sandbox-<version>, which is why the contents are moved up one level.
install_release() {
  mkdir -p "$APP_DIR"
  staging="$APP_DIR/.staging-$1"
  rm -rf "$staging" "$APP_DIR/$1"
  mkdir -p "$staging"
  command -v unzip >/dev/null 2>&1 || die 'launcher: unzip is required'
  unzip -q "$2" -d "$staging"
  mv "$staging/signum-sandbox-$1" "$APP_DIR/$1"
  rm -rf "$staging"

  # The launcher ships with the release, so an update updates it too. Written
  # to a temporary name and renamed, because overwriting a shell script that
  # is currently being read is how a running update corrupts itself.
  if [ -f "$APP_DIR/$1/scripts/signum-sandbox" ]; then
    mkdir -p "$HOME/.local/bin"
    cp "$APP_DIR/$1/scripts/signum-sandbox" "$HOME/.local/bin/.signum-sandbox.new"
    chmod +x "$HOME/.local/bin/.signum-sandbox.new"
    mv "$HOME/.local/bin/.signum-sandbox.new" "$HOME/.local/bin/signum-sandbox"
  fi

  previous=$(installed_version "$INSTALLED_FILE")
  [ -n "$previous" ] && printf '%s\n' "$previous" > "$HOME_DIR/previous"
  printf '%s\n' "$1" > "$INSTALLED_FILE"

  # What is live, and what a rollback would return to. Everything else goes.
  prune_list "$APP_DIR" "$1" "$previous" | while read -r stale; do
    [ -n "$stale" ] || continue
    rm -rf "$APP_DIR/$stale"
    say "launcher: removed the old release $stale"
  done
}

cmd_update() {
  answer=$(curl -fsS -m 20 "https://api.github.com/repos/$REPO/releases/latest" 2>/dev/null || true)
  wanted=$(latest_tag "$answer")
  [ -n "$wanted" ] || die "launcher: could not find out what the newest release is. Is $REPO public and released?"

  current=$(installed_version "$INSTALLED_FILE")
  if [ "$wanted" = "$current" ]; then
    say "launcher: $current is already the newest release"
    return 0
  fi

  say "launcher: updating ${current:-nothing} to $wanted"
  tmp=$(mktemp -d)
  fetch "$(release_url "$wanted")" "$tmp/release.zip"
  sum=$(curl -fsS -m 20 "$(release_url "$wanted").sha256" 2>/dev/null | cut -d' ' -f1 || true)
  if [ -n "$sum" ]; then
    verify "$tmp/release.zip" "$sum" "the $wanted release"
  else
    warn "launcher: the release publishes no .sha256 beside it, installing unverified"
  fi
  install_release "$wanted" "$tmp/release.zip"
  rm -rf "$tmp"
  say "launcher: now on $wanted"
}

cmd_rollback() {
  previous=$(installed_version "$HOME_DIR/previous")
  [ -n "$previous" ] || die 'launcher: no previous release recorded'
  [ -d "$APP_DIR/$previous" ] || die "launcher: $previous was recorded but its directory is gone"
  is_running && die 'launcher: stop the node before rolling back'
  printf '%s\n' "$previous" > "$INSTALLED_FILE"
  say "launcher: back on $previous"
}

cmd_help() {
  cat <<'EOF'
signum-sandbox — a throwaway Signum chain on your own machine

  signum-sandbox                  start it, here, until Ctrl-C
  signum-sandbox start --daemon   start it in the background
  signum-sandbox stop             stop a background node
  signum-sandbox status           version, process, and what the node says
  signum-sandbox logs             follow the log
  signum-sandbox update           move to the newest release
  signum-sandbox rollback         move back to the previous one
  signum-sandbox reset            delete the chain and start from empty

A background node does not survive a logout or a reboot, on purpose: a
sandbox should not keep running unnoticed.

  SIGNUM_SANDBOX_JAVA   use this java instead of the private one
EOF
}

**Two things the spec assumes and this plan works around**, deliberately:

The repository is private and there is no release, so `cmd_update` and `install.sh` cannot be run end to end yet — they are syntax-checked and their decisions are unit-tested, and the whole install path is exercised through `__bootstrap` against a locally built zip in Tasks 9, 12 and 13. Nothing in the plan waits for the repository to go public.

The release zip has no published `.sha256` yet, because that is the release pipeline's job. `cmd_update` therefore verifies when one is there and says plainly that it is installing unverified when it is not, rather than pretending to check.

**One thing the spec did not mention** and Task 8 had to solve: `update` replaces the launcher, which is the script that is running at that moment. It writes the new one to a temporary name in the same directory and renames it over the old, so the running process keeps reading the inode it started with.
